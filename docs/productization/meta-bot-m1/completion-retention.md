# Completion Retention

Completed tasks now have a separate compact white acknowledgement window. Each item has a view-task icon and a confirm icon. The window has no automatic dismissal timer and does not disappear on pointer movement, ordinary task refresh or another task starting. Multiple completions remain separate, including different turns of one task.

Compact row revision: each task occupies one 40px row containing its completed label, ellipsized title and two action icons. The native window is 320px wide and 52px high for one item, including transparent margins and border. Up to six rows are visible before scrolling. There is no separate heading or action footer. Errors replace the affected row's title temporarily, retain the original title in its tooltip, and are announced through a status output. Failed actions never dismiss the item. Browser layout and action tests plus native 150% DPI lifecycle/follow tests passed.

Viewing hands the existing validated task URL to the OS. Only a successful handoff removes that item; a reported launch failure leaves it available with an error. This is not proof that the external application's page finished loading. Confirming removes only the selected completion. Neither action marks a newer running turn as acknowledged.

Setting: `notifications.retainCompletions`, default `true` unless explicitly `false`. The panel gear opens settings and connection diagnostics. Turning retention off hides existing retained items without deleting them and uses the existing brief toast for future completions. Re-enabling restores the retained items; completions received while disabled are not retroactively added.

Preload API: `getNotificationSettings()`, `setRetainCompletions(enabled)`, `onCompletions(listener)`, `completionAction(id, 'open' | 'ack')`. Main-process handlers validate the originating window, resolve task targets themselves and prevent concurrent duplicate actions. Records are stored in `completion-inbox.json` under the configured Meta Bot data directory; source, task ID, title and turn identity are retained rather than full task contents. A failed acknowledgement write keeps the item.

Verification: unit tests cover default-on behavior, restart recovery, duplicate events, separate turns and failed persistence. Browser tests cover persistent visibility, view/confirm icons, launch failure retention, individual dismissal, long titles and settings. Native lifecycle verification waits beyond the old toast timeout, toggles retention off/on through the settings IPC and acknowledges the item through its own window. Active task count and indicator remain independent of retained completions.

Follow-up fix (2026-09-08): completion placement now follows applied ball bounds in scheduled dragging, native moved events and display changes. Movement updates geometry only, without reading settings, republishing content or showing a hidden reminder. Closing the active-task panel restores the completion's adjacent placement. Native lifecycle verification exercises twelve consecutive positions, screen corners and retained identity, passing at default and forced 150% DPI.

The wind-squint pose now uses an asymmetric curved wink. Shared eyelid rendering curves partial closures and completes the white-to-closed-lid crossfade at 75% closure, avoiding residual pale rectangular slits. `test/eye-closure-review.pw.js` checks eight related poses; the existing motion review covers seventeen interaction frames. All 136 unit tests passed. Screenshots: `output/playwright/eye-closure-review.png` and `output/playwright/m1-motion-review.png`.
