# Panel Choreography Release Gate

The start toast and retained completion board are real production windows, not independent animation props. The coordinator first sends `preparing` (100 ms), then unfolds the surface from the robot-facing edge during `entering` (220 ms), and marks it `visible`. Windows are positioned once; compositor transforms replace the previous 13 serial native bounds calls plus 840 ms of fixed waiting. Retrieval lasts 160 ms. Acknowledgement persists first, then retrieves the old board before removing its content. Multiple retained completions use retrieval followed by a new presentation. Opening a task never acknowledges it.

`panel-motion.js` owns the surface animation for all three windows. `expression-controller.js` owns directional gaze and arm poses. Panel work takes precedence over optional masks; drag/high-priority interaction remains protected. Reduced motion in application settings disables transition waiting. System reduced motion disables the surface animation. Native windows no longer travel during animation.

## Scheduling Changes

- Renderer-coordinated masks use minimum start intervals of 120/65/40 seconds, including status/lifecycle triggers. Raw standalone mask-controller compatibility remains unchanged.
- Prop/arm/panel ownership cancels automatic masks; manual mask preview remains explicit. Lifecycle notifications no longer request an additional automatic mask in the same callback.
- Activity selection balances prop families before individual clips and reduces the immediately previous family's weight. State-specific activity pools remain intact.
- These are implemented arbitration rules, not a complete statistical exposure dashboard or a claim that every proposed category quota is enforced.

## Required Checks for Future Changes

1. Run `npm test` including scheduling and asset validity checks.
2. Run `node scripts/build-tauri.cjs`; open `test/fixtures/panel-system.html` or the embedded production demo in `m1-visual.html`.
3. Run `test/panel-system-review.pw.js` via Playwright CLI. It checks real bridge/coordinator events, start/finish/ack, bounded native calls, animation duration budgets and multiple completion handoff. Fix failures, never explain an uninvestigated timeout as cache.
4. Build native, run isolated native smoke and `test/panel-native-handoff.pw.js` against a dedicated test-only CDP process. Never mutate user tasks for tests.
5. Replace the desktop executable only after tests. Verify SHA256 against the tested release binary and verify shortcut target/process path.

Browser fixture mocks only OS window calls and task data. Window `bounds` must return geometry, matching Rust; returning a boolean breaks coordinator geometry. Standalone demo resources are generated by the production build script and are not an independent copy of the UI.
